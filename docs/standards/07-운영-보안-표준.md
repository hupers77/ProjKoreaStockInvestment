# 07. 운영·배포·보안 표준 [보강]

> 이번 프로젝트에서 거의 다루지 않은 영역이다. 개인용 로컬 프로그램이라도 아래 최소 기준을 지킨다.

---

## 1. 실행·자동화

| 항목 | 기준 | 이번 상태 → 개선 |
|---|---|---|
| 자동 스캔 | 앱이 꺼져 있어도 돌아야 하면 OS 스케줄러 사용 | 앱 안 스케줄러만 기본 → 맥 `launchd`/윈도 작업 스케줄러로 `run.py --scan` 등록 방법 제공 |
| 로그인 시 자동 실행 | 선택 기능으로 제공 | 없음 |
| 실행 확인 | 마지막 스캔 시각·결과를 대시보드 상단에 | 스캔 기록에만 있음 |
| 놓친 스캔 | 앱이 켜질 때 오늘 스캔이 없으면 알림/자동 실행 | 없음 |

## 2. 알림

- 스캔 완료/실패, 보유 종목 경고(등급 하락·손절가 이탈·점수 급락), 신규 A 이상 종목.
- 채널: 메일, 텔레그램 봇 등. 알림 내용에 비밀값·계좌 정보는 넣지 않는다.
- 알림 폭주 방지: 하루 1회 요약 + 긴급(손절가 이탈)만 즉시.

## 3. 데이터 보관·백업

- `data/` 폴더 전체를 주 1회 백업 (DB, 캐시, bundle). 압축 후 날짜 이름.
- DB 변경(마이그레이션) 전 자동 백업.
- 보관 기간: 스캔 기록 1년 (이번에 "1년 지난 기록 삭제" 버튼 구현됨), 원천 시세는 영구.
- 삭제 기능은 무엇이 지워지는지 확인 창에 구체적으로 쓰고, 공유 캐시는 지우지 않는다 (이번 투자검증 결과 삭제 방식이 좋은 예).

## 4. 보안

### 4-1. 비밀값
- KRX 비밀번호, DART 키, 증권사 API 키는 **저장소·로그·화면에 평문으로 남기지 않는다.**
- 저장 위치 우선순위: OS 키체인 (`keyring` 패키지) > `.env` 파일(권한 600, `.gitignore` 등록) > DB(암호화).
- 설정 화면에서 비밀번호는 다시 보여주지 않고 "설정됨"만 표시.
- 이번 상태: 설정 DB에 평문 저장 → 개선 대상.

### 4-2. 접속
- 기본은 `127.0.0.1`(내 PC에서만). 이번 구현이 이렇게 되어 있다.
- `--host 0.0.0.0`으로 휴대폰 등에서 접속할 때는 **접속 비밀번호**를 켠다. 같은 와이파이의 다른 사람도 보유 종목·설정을 볼 수 있기 때문.
- 외부(인터넷)에 공개하지 않는다. 필요하면 VPN이나 Tailscale 같은 사설망을 쓴다.
- 데이터를 바꾸는 요청(POST)에는 CSRF 토큰.

### 4-3. 개인정보·공개 전 점검
- [ ] 저장소에 개인 데이터(DB, 보유 종목, 키)가 없는가 (`.gitignore`)
- [ ] 이미지에 실명·얼굴·연락처가 있는가 (이번: 카카오페이 QR에 실명·프로필 사진 포함)
- [ ] 문서·블로그 링크가 비공개 저장소를 가리키지 않는가
- [ ] 라이선스 파일이 있는가 (이번: Elastic License 2.0 추가됨)
- [ ] 면책 문구가 README와 화면에 있는가
- [ ] 데이터 재배포 조건을 확인했는가 (원천 데이터 파일을 저장소에 올리지 않기)

## 5. 배포·업데이트

- 사용자 업데이트 절차를 한 가지로 고정: `git pull` → 패키지 변경 시 설치 → 재시작.
- [보강] 앱 안에 "새 버전 있음" 표시 (GitHub 최신 태그와 비교), 화면 하단 버전 표시.
- [보강] 업데이트 스크립트 `update.sh`: pull + 설치 + 백업 + 재시작을 한 번에.
- Docker 사용 시 데이터 폴더는 볼륨으로 분리.

## 6. 장애 대응

| 증상 | 1차 확인 | 사용자에게 받을 정보 |
|---|---|---|
| 스캔 실패 | 스캔 기록 메시지의 실패 단계 | 메시지 전체, 터미널 앞뒤 20줄 |
| 화면 500 | traceback 마지막 파일·행 | traceback 전체 |
| 점수 이상 | 종목 상세의 항목별 원천값 | 종목코드, 기준일, 캡처 |
| 로그인 실패 | KRX 계정 상태, 비밀번호 변경 여부 | 로그 (비밀번호 제외) |

- 장애를 고친 뒤에는 같은 상황을 재현하는 테스트를 추가한다.
- 사용자 PC에만 있는 데이터를 지워야 할 때는 원격으로 지우려 하지 말고, 화면 버튼이나 정확한 명령을 제공한다.

## 7. 비용·사용량 관리

- 무료 API의 일일 호출 한도를 문서화하고, 스캔 로그에 호출 수를 남긴다.
- 첫 스캔처럼 호출이 많은 작업은 시간대를 밤으로.
- 유료 데이터·서버로 바꿀 때는 월 비용 상한을 기획서에 적는다.
