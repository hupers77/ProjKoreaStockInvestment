## 2. 의존성 관리

- `requirements.txt`에는 범위(`pykrx>=1.2.9,<1.3`), 잠금 파일에는 정확한 버전.
- **데이터 라이브러리(pykrx, FinanceDataReader)는 반드시 상한을 둔다.** 거래소 응답이 바뀌면 라이브러리도 자주 바뀐다.
- 업데이트는 의도적으로: 업데이트 → 테스트 → 실데이터 스모크 → 잠금 파일 갱신.
- 최소 Python 버전을 README 첫 줄과 실행 스크립트 양쪽에서 확인한다 (이번: Python 버전이 낮아 실행 실패).

## 3. 실행 스크립트 (preflight)

`run.sh` / `run.bat`이 시작 전에 확인할 것:

1. Python 버전 (부족하면 설치 방법 안내 후 종료)
2. 가상환경 생성·활성화 (OS 전역 Python 오염 방지)
3. 패키지 설치 여부 (없으면 자동 설치)
4. 포트 사용 여부
5. 데이터 폴더 쓰기 권한
6. 비밀값 설정 여부 (없으면 "설정 화면에서 입력" 안내, 앱은 실행)

## 4. 코드 규칙

### 4-1. 일반
- 함수·변수 이름은 영어, 주석·사용자 메시지는 한국어.
- 판단 규칙서 항목 ID를 그대로 쓴다: `def score_S01(...)`, `K1`, `D4`.
- 매직 넘버 금지: 기준값은 설정/상수 모듈에서 이름 있게.
- 타입 힌트를 쓴다. 금액은 `int`(원), 비율은 `float`(0~1).

### 4-2. 데이터 처리
- **외부 응답은 받자마자 검증**: 필요한 컬럼이 있는지, 비어 있지 않은지. 없으면 `"[KRX 지수 시세] '지수명' 컬럼 없음 (응답 컬럼: …)"`처럼 단계·컬럼·실제 응답을 담아 예외를 낸다.
- **DB 쓰기 전 타입 변환** 함수 하나를 모든 쓰기 경로에서 쓴다.
  ```python
  def native(v):
      if v is None: return None
      if isinstance(v, (np.integer,)): return int(v)
      if isinstance(v, (np.floating,)): return None if np.isnan(v) else float(v)
      if isinstance(v, pd.Timestamp): return v.strftime("%Y-%m-%d")
      return v
  ```
- `None`/`NaN`과 비교·연산 전에 반드시 처리한다. 템플릿에서도 (`{% if x.avg is not none and x.avg > 0 %}`). 이번 투자검증 500 오류의 원인.
- 0과 결측을 구분한다.
- pandas 경고(SettingWithCopy 등)를 무시하지 않는다.

### 4-3. 외부 호출
- 타임아웃 필수, 재시도는 지수 백오프로 최대 3회.
- 호출 사이 간격(rate limit) 준수.
- 실패해도 다음 단계 진행, 경고 목록에 누적.
- 라이브러리가 import 시점에 부작용(자동 로그인 등)을 일으키면, import 전에 환경 변수를 먼저 설정한다 (이번 KRX "로그인 실패" 콘솔 메시지 사례).

### 4-4. 로그
- [보강] 콘솔과 함께 `data/logs/app.log`(일자별 회전)에 남긴다.
- 스캔 로그에는 단계명, 처리 건수, 소요 시간, 경고를 남긴다.
- 비밀번호·API 키는 로그에 남기지 않는다 (마스킹).

### 4-5. DB 변경 (마이그레이션)
- 앱 시작 시 스키마 버전을 확인하고 필요한 변경을 순서대로 적용.
- 기존 데이터를 고칠 수 있으면 자동으로 고친다 (이번: bytes 시가총액 자동 복구, 18:30→20:30 1회 변경). 사용자가 다시 스캔하지 않게.
- 변경 전 DB 파일을 자동 백업 (`stock.db.bak-YYYYMMDD`). [보강]
- 내부 키(id)를 바꾸지 않는다. 표시용 번호는 별도로 (이번 스캔 번호 사례의 판단이 맞았다).

## 5. 브랜치·커밋·배포

- 기본: `main`은 항상 실행 가능한 상태.
- 기능은 브랜치 → PR → CI 통과 → 병합. 혼자 쓰는 프로젝트라도 CI는 붙인다.
- 커밋 메시지: `[화면/영역]: 무엇을` (한국어 가능). 예: `투자검증: 기준일 이후 시세가 없을 때 500 오류 수정`. 이번 커밋 메시지 스타일은 좋았다.
- [보강] 사용자에게 영향이 있는 변경은 `CHANGELOG.md`에 기록, 의미 있는 묶음마다 태그(`v1.3.0`).
- [보강] 화면 하단에 버전과 커밋 해시 표시 → 사용자가 "업데이트가 됐나"를 바로 확인.
- 업데이트 안내는 항상 같은 형식: `git pull` → (패키지 변경 시) `pip install -r requirements.txt` → 재시작 → (필요 시) 지금 스캔.

## 6. 성능 기준

| 작업 | 목표 | 이번 실측/추정 |
|---|---|---|
| 첫 전체 스캔 | 60분 이내 | 10~30분 (+DART 30~60분) |
| 같은 날 재스캔 | 5분 이내 | 증분 수집으로 단축 |
| 재계산 (전 종목) | 30초 이내 | 데모 300종목 3초, 실데이터 약 20초 |
| 화면 응답 | 1초 이내 | |

- 무거운 데이터는 제외 필터를 통과한 종목만 받는다.
- 큰 결과는 압축 저장 (`.pkl.gz`). [보강] pickle은 버전 호환성이 약하므로 장기 보관용은 parquet 고려.
