## 3. 잘된 점 (계속할 것)

1. **평가 기준서를 먼저 만든 것.** 62개 항목, 제외 필터, 가·감점, 등급 게이트가 문서로 있어서 채점 엔진을 한 번에 만들 수 있었고, 이후 질문("커버리지 바꾸면 어떻게 되나")에도 근거를 댈 수 있었다. 경제 프로그램에서 가장 중요한 산출물은 코드가 아니라 이 "판단 규칙서"다.
2. **무료 데이터 경로를 먼저 확정.** KRX 계정 + OpenDART 키 + FDR 조합으로 비용 0원에 운영 가능.
3. **데모 데이터 모드.** 네트워크가 막힌 환경에서도 전 화면과 채점을 검증할 수 있었고, 이후 "기능 검증용"으로 남겼다.
4. **기준서와 다르게 처리한 부분을 README에 전부 기록.** 기록하는 과정에서 K1·D4 버그를 찾았다.
5. **재계산(데이터 조회 없이 다시 채점).** 사용자가 직접 제안한 것으로, 수집과 채점을 분리하는 좋은 설계가 되었다.
6. **짧은 반복 주기.** 대부분의 요청이 2~5분 안에 반영·푸시되었다.
7. **투자검증에서 미래 정보 차단을 고려.** DART 공시 시차를 기한 기준으로 근사하고, 근사한 부분을 문서에 밝혔다.

## 6. 다음 프로젝트에 가져갈 원칙 7가지

1. **판단 규칙서 먼저, 코드는 나중.** 점수·신호·등급 규칙은 문서로 확정하고 버전을 붙인다.
2. **실데이터로 첫날 한 번 돌린다.** 못 돌리면 그 사실과 위험을 첫 응답에 명시하고, 사용자 PC에서 돌릴 방법을 바로 마련한다.
3. **수집 · 계산 · 표시를 분리한다.** 다시 계산할 때 다시 받지 않는다.
4. **"데이터가 없을 때"를 먼저 설계한다.** 첫 실행, 휴장일, 장중, 응답 비어 있음, 상장폐지.
5. **백테스트는 의심부터 한다.** 미래 정보, 생존 편향, 비용, 과최적화를 점검표로 확인한다.
6. **표시 방식은 그림으로 먼저 고른다.** 색·아이콘·차트는 시안 2~3개.
7. **투자 판단은 사용자 책임임을 화면과 문서에 밝힌다.** 공개·배포 전에는 법·개인정보 점검.
