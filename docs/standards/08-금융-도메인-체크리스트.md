# 08. 경제·금융 도메인 체크리스트 [보강]

> 경제·금융 프로그램에서만 생기는 함정을 모았다. 기획과 설계 단계에서 항목마다 "해당 없음 / 처리 방법"을 적는다.

---

## 1. 시장 일정과 시간

- [ ] 거래 시간, 장 종료 후 데이터 확정 시각 (이번: 장 종료 20시로 바뀌어 기본 스캔 18:30 → 20:30 수정). **코드 상수가 아니라 설정으로.**
- [ ] 휴장일 (공휴일, 연말 휴장, 임시 휴장, 선거일). 요일만 보고 판단하지 않는다.
- [ ] 기준일 = "직전 확정 거래일". 주말·휴일 스캔 시 처리.
- [ ] 시간대 `Asia/Seoul` 고정, 해외 시장을 다룰 때는 시장별 시간대.
- [ ] 장중 값과 확정 값 구분.

## 2. 가격 데이터

- [ ] **수정주가**: 액면분할·병합, 무상증자, 배당락. 수정하지 않으면 분할일에 가짜 −80% 수익률이 생긴다.
- [ ] 거래정지·관리종목·투자경고 상태.
- [ ] 신규 상장(이력 부족), 상장폐지(시세 끊김) 처리.
- [ ] 시장 구분 변경 (KOSDAQ → KOSPI 이전 상장).
- [ ] 종목코드 재사용·변경, 우선주·스팩·ETF·ETN·리츠 구분.
- [ ] 가격 제한폭(±30%), 호가 단위.

## 3. 재무 데이터

- [ ] 연결/별도 재무제표 중 무엇을 쓸지.
- [ ] 보고서 종류: 사업(연간)·반기·분기, 누적/분기 단독 값 구분.
- [ ] **공시일 기준**으로만 사용 (분기말 + 45일, 사업연도말 + 90일이 법정 기한).
- [ ] 정정 공시: 정정 전 값과 후 값 중 백테스트에는 당시 값.
- [ ] 회사마다 다른 계정 이름 (이번: DART 계정명이 달라 일부 N/A 가능). IFRS 계정 ID 우선, 이름은 보조.
- [ ] 결산월이 12월이 아닌 회사.
- [ ] 금융업(은행·보험·증권)·지주사는 일반 지표(부채비율, 영업이익률)가 맞지 않음 → 업종별 대체 규칙.

## 4. 지표 계산

- [ ] PER·PBR 음수(적자) 처리.
- [ ] TTM(최근 4분기 합) vs 연간 값.
- [ ] 시가총액 = 보통주 기준인지, 우선주 포함인지.
- [ ] 배당수익률 = 최근 확정 배당 기준.
- [ ] 이상치(극단값) 처리: 분위수 자르기, 업종 내 순위로 변환.
- [ ] 업종 분류 기준과 변경 이력.

## 5. 투자 판단 규칙

- [ ] 점수 → 등급 → 행동(매수 검토/관찰/제외)의 연결이 문서화되어 있는가.
- [ ] 손절가·목표가 산정 규칙.
- [ ] 포지션 크기·분산 규칙 (한 종목 비중 상한).
- [ ] 판단 규칙 변경 시 버전과 검증 결과를 남기는가.
- [ ] 수동 입력(정성 평가)의 근거와 입력일을 남기는가.

## 6. 성과 측정

- [ ] 수익률 계산식 (단순/로그, 배당 포함 여부).
- [ ] 거래 비용: 수수료, 증권거래세(매도, 시장·연도별 세율), 슬리피지.
- [ ] 세금: 배당소득세 15.4%, 대주주 양도세 등은 개인 상황이라 표시만.
- [ ] 벤치마크 선택과 같은 기간 비교.
- [ ] 위험 지표: 최대 낙폭(MDD), 변동성, 샤프지수, 승률, 손익비.
- [ ] 백테스트 점검표 → [06-테스트](06-테스트-표준.md) 5장.

## 7. 법·규제·약관 (공개·배포 시 필수)

> 아래는 일반적인 확인 항목이며 법률 자문이 아니다. 공개·판매 전에는 전문가에게 확인한다.

- [ ] **투자 권유 여부**: 특정 종목 매수·매도를 불특정 다수에게 권하면 유사투자자문업 신고 등 규제 대상이 될 수 있다. 개인용 도구로 쓰는 것과 결과를 공개·판매하는 것은 다르다.
- [ ] **면책 문구**: "정보 제공 목적, 투자 권유 아님, 투자 판단과 책임은 사용자에게 있음, 과거 성과가 미래 수익을 보장하지 않음".
- [ ] **데이터 이용 약관**: KRX 정보데이터시스템, OpenDART, 기타 출처의 개인 이용·재배포·상업적 이용 조건. 원천 데이터를 저장소나 블로그에 그대로 올리지 않는다.
- [ ] **개인정보**: 보유 종목·매수가·계좌 정보는 개인 금융 정보. 저장 위치와 공유 범위를 정한다.
- [ ] **자동 매매**: 증권사 API로 주문까지 하면 주문 오류·중복 주문 방지, 한도, 수동 확인 단계가 필수. 이번 프로젝트는 "자동 매매 안 함"으로 범위를 정한 것이 적절했다.
- [ ] **후원·수익화**: 후원 링크와 투자 정보가 같은 화면에 있을 때 오해가 없도록 분리 표시.
- [ ] **오픈소스 라이선스**: 사용한 라이브러리 라이선스와 자기 코드 라이선스 (이번: Elastic License 2.0).

## 8. 다른 경제 프로그램에 적용할 때 추가 항목

| 프로그램 종류 | 추가 확인 |
|---|---|
| 가계부·자산관리 | 계좌 연동 인증(오픈뱅킹), 카테고리 규칙, 통화·환율, 개인정보 암호화 |
| 포트폴리오 리밸런싱 | 목표 비중, 리밸런싱 주기·임계값, 세금 영향, 최소 주문 단위 |
| 환율·해외주식 | 시장별 시간대·휴장일, 환전 비용, 원화 환산 기준 시점 |
| 채권·예금 | 일수 계산 방식(Act/365 등), 복리 주기, 세후 이자 |
| 연금·은퇴 계산기 | 물가상승률·수익률 가정 표시, 시나리오(낙관/기본/비관), 세제 혜택 한도 |
| 경제 지표 대시보드 | 발표 일정, 수정치(revision), 계절조정 여부, 출처(한국은행 ECOS, KOSIS) |
| 자동 매매 | 주문 상태 관리, 체결 확인, 장애 시 정지(킬 스위치), 모의투자 먼저 |
